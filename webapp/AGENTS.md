# webapp/AGENTS.md

Scoped instructions for the React/TypeScript webapp in `webapp/`. Root rules in `/AGENTS.md` still apply; only deviations and package-specific gotchas live here.

- Single Jest test: `cd webapp && npx jest src/path/file.test.tsx`. Jest gotchas: `jest.config.js` compiles `.ts`/`.tsx` with `ts-jest` (not Babel), so `babel-plugin-formatjs` does not inject message IDs — mock `react-intl` (`useIntl`/`FormattedMessage`, see `agent_chat_title_bar.test.tsx`) instead of wrapping in a real `IntlProvider`; `@testing-library/jest-dom` is not installed (`tests/setup.tsx` is empty); Jest 30 uses `--testPathPatterns` (plural); jsdom lacks `element.innerText` and does not resolve CSS custom properties (`var(--*)`).
- Styling: **always `styled-components`**, never inline `style={{...}}`.
- Non-default ESLint rules (`webapp/eslint.config.mjs`): `no-undefined` (use conditional prop spreads `{...(cond ? {prop} : {})}` instead of `: undefined`), `no-mixed-operators` (`allowSamePrecedence: false` — split compound updates like `j += run - 1`), `wrap-regex`/`no-div-regex`, `lines-around-comment`, `no-empty-function` (use `jest.fn()` in tests), `consistent-return`, and `max-lines` (450). Always re-run `cd webapp && npm run lint` after any cleanup edit (pass `--no-cache` if cached output looks stale; CI runs `eslint . --quiet --cache`, ignoring pre-existing `import/no-named-as-default` warnings on `styled`).
- i18n: never hand-edit `webapp/src/i18n/en.json` — add user-facing strings at call sites (`react/jsx-no-literals` enforces this) and run `make check-style-fix` or `make i18n-extract`. On merge conflicts in `webapp/src/i18n/en.json`, reset to the base branch (`git checkout origin/master -- webapp/src/i18n/en.json`) and run `make i18n-extract`.
- E2E copy coupling: when changing user-facing labels, headings, or settings help text, grep `e2e/` (`tests/` and `helpers/`) for the old strings and update matching Playwright locators in the same PR.
- Host boundaries and utilities: before writing custom parsers or formatters (e.g. markdown stripping), check host globals (`window.PostUtils`, `window.WebappUtils`, `window.Components`; typed in `webapp/src/types/mattermost-webapp/index.d.ts`). Do not CSS-hide, scrape, or synthetically click host-owned UI chrome (e.g. `AdvancedTextEditor` controls) when the change belongs in `mattermost/mattermost`.
- `@mattermost/compass-ui` is pre-1.0 (`0.1.0-alpha.*`): after bumping its version, run the full webapp suite (`cd webapp && npm test`) rather than only the touched component — alpha updates change defaults and styles (e.g. `Combobox` `openOnFocus`).
- System Console & `Client4`: in `src/components/system_console/`, wire `SettingsReadOnlyContext` so controls disable while saving and link field errors via `aria-describedby`. `@mattermost/client` `Options` is narrower than DOM `RequestInit` (no `cache`/`redirect`).
- Host editor contract: `webapp/src/types/access_control_editors.ts` mirrors Mattermost host `window.Components` access-control editor props and is checked against `webapp/src/types/host_editor_contract.snapshot.d.ts` by `npm run check-editor-contract` (runs in `make check-style` and CI). Regenerate the snapshot with `npm run update-editor-contract-snapshot` when a host checkout is available (`MM_WEBAPP_PATH` or sibling `../mattermost/webapp`).
- Async loaders ignore responses from superseded requests (track the latest request, or cancel on input change and unmount) so a stale response never overwrites newer state.
- Use `@mattermost/compass-ui` components (buttons, icon buttons, tabs, radio groups, modals, menus) instead of hand-rolled interactive elements; anything clickable is keyboard-operable and has an accessible label.
- Spacing (padding, margin, gap) uses compass `--spacing-*` tokens, not raw px.
- Host CSS variables such as `--border-light` are whole shorthands (`border-bottom: var(--border-light)`), not colors; `1px solid var(--border-light)` is invalid.
- Plugin modals sit at z-index 2000 and their menus at 2100, above the host tooltip layer (1350). A host `WithTooltip` inside a modal renders behind it: use `TooltipAboveModals` from `@/components/dropdown`, and prefer `DotMenu` triggers (which already do).
- A modal is an `AnimatedModalShell` (scrim, Escape, exit fade) around a compass `Modal`, and the `Modal` gets `open={show}` too: without it the sheet has no enter or exit motion, only the scrim fades. Use the shell for every modal, nested ones included (a modal opened from inside another stacks above it and takes Escape).
- Popover menus animate through compass `PopoverMenu` `open`/`onExited`; a `Dropdown` must stay mounted until `onExited` (`useMenuTransition`), as `DotMenu` does. Passing no `open` renders the menu with no animation. This is plugin-side glue: compass-ui plans to provide more of it (positioning and open/close handling for menus), so check the installed compass-ui for that before extending `useMenuTransition` or `Dropdown`, and drop the glue once compass covers it.
- The `agents/*` lint rules are jsx-a11y rules that resolve styled-components declared in the same file to their DOM tag. Styled components imported from another file are invisible to them, so prefer native elements (`styled.button`) over adding handlers to imported wrappers. Suppress a legitimate JSX violation with `{/* eslint-disable-next-line agents/<rule> -- <reason> */}` directly above the opening tag (not `jsx-a11y/<rule>`, and not a `//` comment on a prop line).
- HTML artifact frames (`webapp/src/components/html_artifacts/`): keep one teardown path that both rejects and clears pending consent prompts (updating the ref synchronously with state, never only on render, so stop/reload cannot leak the page-wide prompt lock or leave an armed prompt on screen); never set `startedByClick` from deep links/URLs; refresh the heartbeat watchdog (`onHostBusy`) around slow host decoding; and keep artifact-controlled filenames separate from host-written consent sentences.
